# Terminal output publication recovery

The gateway database exhaustion had a second effect. Mac commands completed, but artifact.put failed. The adapter exited1 and deleted its TemporaryDirectory. The generic worker correctly retained uncertainty, which then blocked later commands in the same slot. Captured local tracebacks identify this exact post-exit failure in slots8,10,11,13,14,15. A separate permission failure and receipts without completion evidence remain unresolved.

The Mac adapter now writes a durable per-operation launch/completion receipt and retains stdout/stderr before uploading artifacts. A finished exact request can republish its output without executing its argv again. Identity changes and unfinished launches are rejected. A separate receipt publisher resumes finished receipts and uses the existing provider/generation/signature-checked reconciliation path. It cannot run or stop terminal commands. It is installed independently so the live terminal worker and active jobs do not restart. The regular installer bundles and starts it at boot. Existing successful and uncertain history stays intact.

Files are retained below terminal-results/SHA256(operation). No new job timeout, CPU limit, retry-count ceiling or automatic output purge is introduced. Five seconds is the receipt-publisher polling interval, not a command deadline. Retained output and operation receipts require explicit lifecycle management; recovery does not claim unbounded host disk capacity. The process-group cleanup policy remains as before; an unresolved launch/cleanup failure stays unresolved with its output retained.

They cover failed output upload, exact retry with a one-execution counter, changed identity rejection, no replay of unfinished launches, receipt publication, and no unsolicited duration limit.
